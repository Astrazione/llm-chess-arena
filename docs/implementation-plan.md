# План реализации

Статус этапа 1: **завершён и проверен в Docker Desktop на Windows**, 15 ноября 2026 года. Остальные этапы не начаты. Полные требования находятся в [requirements.md](requirements.md), границы компонентов — в [architecture.md](architecture.md).

## Этап 1. Архитектура и Docker-окружение

- [x] Определить ответственность компонентов и контракт LLM Provider.
- [x] Разделить React/Vite/TypeScript frontend и Fastify/TypeScript backend.
- [x] Dockerfile, Compose, bind mounts, изоляция node_modules, polling, внутренний DNS и API-прокси.
- [x] Volume экспериментов, проверка каталога данных, health checks и graceful shutdown.
- [x] `.env.example`, Git/Docker ignore, server-only secrets, непривилегированный пользователь.
- [x] `/api/health`, страница проверки backend, unit/API и браузерные тесты.
- [x] Контейнерные lint/typecheck/test/build, README и AGENTS.md.
- [x] Проверить `docker compose up --build -d`, health, состояние и логи.
- [x] Проверить frontend/backend и связь в настоящем браузере.
- [x] Выполнить lint/typecheck/test/build обоих сервисов внутри Docker.
- [x] Проверить hot reload frontend/backend без пересборки.
- [x] Проверить корректную остановку, пересоздание и сохранность JSON в volume.

Критерий готовности: все пункты выше подтверждены запуском. Отчёт: [verification.md](verification.md). Если Docker недоступен, этап остаётся незавершённым.

Сопровождение окружения: отслеживать обновление транзитивного minimatch в nodemon/typescript-eslint; текущие moderate-предупреждения npm audit и границы платформенной проверки описаны в отчёте.

## Этап 2. Chess Engine и доменные контракты

- [ ] Подключить актуальный chess.js, определить snapshot, UCI, outcome и ошибки.
- [ ] Начальная позиция, легальные ходы, FEN/ASCII/история и PGN.
- [ ] Проверить нелегальный ход без изменения позиции, рокировку, en passant, превращение, шах, мат, пат и ничьи.

Готово, когда все изменения позиции проходят через Engine и специальные правила покрыты содержательными контейнерными тестами.

## Этап 3. Оркестратор и Mock Provider

- [ ] Mock Provider: заданные ходы, неверный JSON/формат, пустой ответ, IllegalMove, ProviderError и задержки.
- [ ] Parser, Prompt Builder с редактируемым шаблоном, одинаковые правила для двух цветов, режимы A/B.
- [ ] Start/Pause/Resume/Next Move/Stop/Reset, retries, лимит полуходов и техническое поражение.
- [ ] Один активный ход; отмена и защита от запоздавших ответов.
- [ ] Ошибки и попытки, счётчики и время ответа.

Готово, когда партии между mock-моделями воспроизводимы, Pause во время запроса и Reset/Stop с незавершённым запросом безопасны, Next Move не запускает второй ход.

## Этап 4. API матчей, события и хранение

- [ ] Валидируемые DTO и команды, публичные snapshots, versioned SSE с heartbeat/reconnect.
- [ ] JSON Store с атомарной записью, logger всех попыток, восстановление сохранённых результатов.
- [ ] Экспорт PGN и полного JSON; сохранение завершённых и остановленных матчей.
- [ ] Тесты экспорта, SSE, ошибок хранения, секретов и shutdown во время запроса.

Готово, когда матч можно провести через API, события согласованы с серверным состоянием, JSON переживает пересоздание, секретов нет в файлах/DTO/логах.

## Этап 5. Интеграция LLM и локальные runtimes

- [ ] OpenAI-compatible Chat Completions adapter, проверка модели и параметров перед стартом.
- [ ] Независимые base URL/model ID/параметры двух игроков, env keys, timeout/cancellation и capability diagnostics.
- [ ] OpenAI/OpenRouter/Ollama, внешние vLLM CUDA/vLLM-Metal и Docker Model Runner.
- [ ] Необязательный profile nvidia: официальный образ с проверенной поддержкой Blackwell sm_120, GPU/cache/context/memory limits.
- [ ] Документация CUDA/Windows WSL2/macOS Apple Silicon, OOM-диагностика и ресурсные ограничения двух endpoints.
- [ ] Метаданные runtime/model revision/quantization/context, токены и время загрузки/генерации, когда доступны.

Готово, когда две реальные модели независимо подключаются и ходят; тесты протокола работают без реальных ключей, отсутствие GPU не мешает базовому запуску. Версии vLLM и GPU-совместимость подтверждены отдельно.

## Этап 6. Интерфейс матча

- [ ] react-chessboard, панели игроков/настроек, режимы A/B и system prompt.
- [ ] Команды, состояния запроса/ошибок, история ходов, подсветка последнего/ошибочного хода.
- [ ] Просмотр истории без изменения игры, журнал, статистика и экспорт.
- [ ] Адаптивная тёмная тема и e2e-проверки критических действий.

Готово, когда пользователь может настроить два LLM, провести и остановить матч, увидеть ошибки и экспортировать результаты.
