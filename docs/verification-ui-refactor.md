# Проверка рефакторинга интерфейса

Дата: 16 ноября 2026 года. Среда: Windows, Docker Desktop/WSL2, Linux-контейнеры Node.js 24 и Chromium Playwright. Все исполняемые проверки проводились через Docker Compose; host node_modules не создавались. Зависимости и lock-файлы не менялись.

## Выполненные изменения

- App: компактный header, отдельная страница истории, один useMatch/SSE, сохранение текущего workspace при просмотре архива.
- MatchWorkspace/Player: прежняя доска react-chessboard и палитра, компактные модели с провайдером/статусом/ходами/ошибками/ответом, управление и история позиций под доской. При узкой колонке действия отображаются иконками с title и aria-label.
- MatchInfo/EventLog/Statistics: вкладки Обзор/Ходы/Журнал, независимая прокрутка, выбор SAN и автопрокрутка к выбранной/последней позиции, все прежние метрики и диагностика, меню экспорта. Последний ход, статус и ошибки доступны над вкладками.
- Settings/PlayerSettingsForm/Modal/Tabs: drawer 520 px, три вкладки, одна переиспользуемая форма цвета, черновик вне жизненного цикла вкладок, закреплённая кнопка применения, focus trap/возврат фокуса, Escape/клик снаружи/кнопка закрытия. Неверное поле на скрытой вкладке раскрывается и получает фокус.
- Experiments: короткие «Назад»/«Вперёд» без фиксированной ширины, очистка с явным подтверждением количества, предупреждением о необратимости, состояниями загрузки/ошибки и обновлением страницы после удаления.
- Backend: расширен только порт ExperimentStore, JSON adapter, MatchService для определения защищённых gameId, контракты и маршруты архива. Game Orchestrator, Chess Engine, LLM-адаптеры, механизм SSE не изменены.

## Очистка истории

GET `/api/experiments/cleanup` возвращает точные ID допустимых Completed/Stopped. DELETE `/api/experiments` получает подтверждённые gameIds, повторно читает/валидирует записи и сохраняет Created/Running/Paused, busy и защищённые активные игры. Новые завершившиеся партии после preview не добавляются к удалению. Удаление только UUID JSON из DATA_DIR, затем fsync каталога; посторонние и повреждённые файлы сохраняются. Ответ содержит deleted/skipped/failed; частичный отказ не выдаётся за полный успех. Пустой список безопасен, повторные ID уже удалённых файлов пропускаются.

Четыре новых backend-теста проверяют завершённые/остановленные/Reset-игры, активные Created/Paused/Running, неверные/поддельные ID, лишние поля и дубли, пустой список, повтор запроса, новые завершившиеся партии после подтверждения, сохранность прочих/повреждённых файлов, реальный отказ unlink через chmod и отсутствие восстановления удалённых JSON после restart. Прежние тесты сохранены.

## Ограничения

- Проверен Chromium; отдельные прогоны Firefox/Safari и настоящий browser zoom не выполнялись. Увеличение шрифта и переход к прокрутке при малом viewport проверены отдельно.
- Реальные платные LLM и настоящий Ollama повторно не вызывались. Существующий NVIDIA runtime сохранён; generation в рамках этого рефакторинга не выполнялась. Автоматические тесты используют Mock и локальный тестовый HTTP API.
- Очистка всего набора JSON не транзакционна: уже удалённые записи не восстанавливаются при ошибке другого файла. UI сообщает частичные ошибки. Повреждённые файлы не удаляются автоматически.
- До перезапуска завершённый snapshot может оставаться в RAM после удаления его JSON; экспорт удалённого gameId возвращает 404. Активные игры остаются на диске, а просмотр архива не управляет ими.
- Для очень больших архивов сохраняется линейное чтение файлов существующего хранилища. Новые индексы, БД и фоновые очереди не добавлялись.

Текущий рефакторинг завершён; последующие исследовательские этапы не начаты.
